### 📋 Схема таблиц базы данных

#### 1. Таблица `envelopes` (Кубышки / Конверты)
Хранит информацию о ваших целевых конвертах.

| Поле | Тип данных | Описание |
| :--- | :--- | :--- |
| **`id`** | INT / UUID (PK) | Уникальный идентификатор конверта. |
| **`created_at`** | TIMESTAMP | Дата и время создания конверта (по умолчанию `NOW()`). |
| **`name`** | VARCHAR(255) | Название (например, «На отпуск», «Подушка безопасности»). |
| **`description`** | TEXT (Nullable) | Описание цели или заметки. |
| **`is_active`** | BOOLEAN | Статус (активен/архивирован), чтобы скрывать старые конверты. |
| **`user`** | 'max' or 'sasha' | юзер |

#### 2. Таблица `savings_operations` (Операции)
Хранит все движения денег: пополнения, траты и переводы.

| Поле | Тип данных | Описание |
| :--- | :--- | :--- |
| **`id`** | INT / UUID (PK) | Уникальный идентификатор операции. |
| **`created_at`** | TIMESTAMP | Дата и время проведения операции. |
| **`envelope_id`** | INT / UUID (FK) | Ссылка на конверт, в котором происходит движение. |
| **`amount`** | NUMERIC / INT | Сумма операции. **Положительная** для прихода, **отрицательная** для расхода. |
| **`currency`** | 'RUB' | 'EUR' | 'USD' | 'AMD' | 'RSD'; | валюта |
| **`operation_type`** | VARCHAR(20) | Тип: `DEPOSIT` (доход), `WITHDRAWAL` (расход), `TRANSFER_OUT` (ушло переводом), `TRANSFER_IN` (пришло переводом). |
| **`description`** | TEXT (Nullable) | Комментарий к операции (например, «Премия» или «Купил билеты»). |
| **`related_operation_id`**| INT / UUID (FK) | Ссылка на `id` в этой же таблице. **Заполняется только для переводов** (связывает списание и зачисление). Safe to be NULL. |
| **`user`** | 'max' or 'sasha' | юзер |


---

### 💡 Как это работает на практике (Примеры)

1. **Вы просто положили в конверт «На отпуск» (id: 1) 5 000 рублей:**
   * `envelope_id`: 1, `amount`: 5000, `operation_type`: `'DEPOSIT'`, `related_operation_id`: `NULL`
2. **Вы перевели 2 000 рублей из конверта «Подушка» (id: 2) в конверт «На auto» (id: 3):**
   В базу запишутся **две строки**, которые ссылаются друг на друга через `related_operation_id`:
   * *Строка 1 (Списание):* `id`: 101, `envelope_id`: 2, `amount`: -2000, `operation_type`: `'TRANSFER_OUT'`, `related_operation_id`: 102
   * *Строка 2 (Зачисление):* `id`: 102, `envelope_id`: 3, `amount`: 2000, `operation_type`: `'TRANSFER_IN'`, `related_operation_id`: 101

### 🔍 Как теперь легко считать данные:
* **Текущий баланс конверта №1:** `SELECT SUM(amount) FROM savings_operation WHERE envelope_id = 1;`
* **История переводов для конверта №1:** `SELECT * FROM savings_operation WHERE envelope_id = 1 AND operation_type IN ('TRANSFER_IN', 'TRANSFER_OUT');` (а через `related_operation_id` вы всегда сможете вытянуть парный конверт, чтобы показать пользователю: *"Перевод из конверта 'Подушка'"*).
